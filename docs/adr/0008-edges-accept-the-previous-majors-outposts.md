# Edges accept Outposts of their own and the previous major

Any Edge and Outpost of the same major version work together, whichever is newer, and an Edge of a new major also accepts the previous major's Outposts. The Edge is the judge: it learns each Outpost's version from the pings inside the Tunnel and refuses only Outposts outside that window. An Outpost refuses only an Edge of an older major, because it can't know whether a newer major still accepts it. So every upgrade goes Edge first, then each Outpost whenever the operator gets to its machine. We chose this over lockstep majors, where upgrading the Edge to 2.0 would take every 1.x Outpost offline until someone reaches it, and over an Edge that must always be the newest, which would break an Outpost upgraded first. Because the Outpost holds no Route table ([ADR 0001](0001-outpost-holds-no-route-table.md)), the old protocol a new Edge must keep is small: the tnl header, the join token and the Tunnel API. The cost is a promise that binds the next major. The 2.x Edge must still speak all three as 1.x did, every protocol change within a major must be additive, and both sides refuse fields they don't know rather than ignore them. Releases before 1.0 promise less: two 0.x versions work together only within one minor.

See [Version skew between Edge and Outpost](https://github.com/hyprsh/tnl/issues/15).

Amended by [ADR 0012](0012-clients-read-replies-leniently.md): a client reads the `ls` and status replies and an Outpost's own Routes leniently, ignoring a field it doesn't know, rather than refusing it.
