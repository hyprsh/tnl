# HSTS is on by default and the Edge's replies send no Server header

The Edge adds `Strict-Transport-Security: max-age=31536000` to every HTTPS reply unless the Service sent its own, removes the `Via: 1.1 Caddy` that Caddy puts on replies, and sends no `Server` header on the replies it makes itself (Caddy sets `Server: Caddy` on every response, and the Edge deletes it). Its own replies also carry `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and a `Content-Security-Policy` that allows only the page's inline CSS. A Service's own `Server` passes through. HSTS has no per-Route switch and Routes can't add headers: either would be a new Route field, which restarts the 1.0.0 clock. We chose on-by-default because every Route is served over HTTPS only, so HSTS costs a Visitor nothing, and an HTTPS-only Edge that did not send it would fail scanners for no reason. The cost is that a Visitor's browser, once it has seen the header, refuses plain HTTP to that Hostname for a year, and the Edge can't turn that off for one Route. `Server: tnl` was rejected because it names the software to anyone scanning for it. This changes what Visitors see over HTTP, not a wire format or `state.json`.
