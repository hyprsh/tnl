# HSTS is on by default and the Edge's replies send no Server header

The Edge adds `Strict-Transport-Security: max-age=31536000` to every HTTPS reply unless the Service sent its own, removes the `Via: 1.1 Caddy` that Caddy puts on replies, and sends no `Server` header on the replies it makes itself (Caddy sets `Server: Caddy` on every response, and the Edge deletes it). Its own replies also carry `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and a `Content-Security-Policy` that allows only the page's inline CSS. A Service's own `Server` passes through. A Route can turn HSTS off with `--no-hsts` and add response headers with `--header` (added to the Service's replies only, the Service's own header wins; the Edge's own replies keep their fixed headers and get no extra ones). They shipped in 0.2.0, after the first cut of this decision, as a new Route field in `state.json`, the Tunnel API and the Declaration. We chose on-by-default because every Route is served over HTTPS only, so HSTS costs a Visitor nothing, and an HTTPS-only Edge that did not send it would fail scanners for no reason. The cost is that a Visitor's browser, once it has seen the header, refuses plain HTTP to that Hostname for a year, and a Route that must not send it needs `--no-hsts` from the start, because a browser that has seen the header keeps it. `Server: tnl` was rejected because it names the software to anyone scanning for it. The defaults change what Visitors see over HTTP; the per-Route options change the wire format and the schema of `state.json`.
