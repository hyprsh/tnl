# DNS tokens stay out of Caddy's config

A wildcard Zone's DNS provider token lives in tnl's state, never in Caddy's config. Caddy's config names only the Zone, and one tnl-owned module in Caddy's `dns.providers` namespace reads that Zone's provider and current token from tnl's state when a challenge runs, then calls the provider's libdns package. We chose this over reusing the caddy-dns modules, which would put tokens in Caddy's JSON (autosaved to disk and served by the admin API unless both are switched off), reload Caddy on every token change, and echo a rejected Cloudflare token in error messages. We also rejected driving certmagic ourselves, which would avoid every reload but make tnl own certificate storage, renewal and serving. The cost is that adding, removing or switching the mode of a wildcard Zone still reloads Caddy, which closes every WebSocket on every Route while Server-Sent Events streams survive. That is acceptable for a rare operator action, and per-Hostname Zones never touch Caddy's config. Providers stay compiled into the binary: adding one means a libdns import and a small entry in tnl, not a caddy-dns module.

See [Zones and certificate modes](https://github.com/hyprsh/tnl/issues/8).
