# Outposts join inside the Tunnel with a one-time WireGuard key

Adding an Outpost on the Edge creates a one-time WireGuard key pair and prints a join token holding its private half, the Edge's public address and the Edge's WireGuard public key. The Outpost brings the Tunnel up with that key, then registers a key pair it generated itself with the Edge at `100.64.0.1`, inside the Tunnel, and the Edge swaps the peer and forgets the one-time key. We chose this over a join endpoint on public HTTPS (Tailscale, Pangolin, kubeadm), which needs an Edge Hostname and certificate before the first Outpost can join and puts an unauthenticated endpoint on the internet. We also chose it over a long-lived token that is itself the credential (cloudflared), which passes the private key through the operator's clipboard and lets anyone holding a leaked token impersonate the Outpost until it's revoked. This way the Edge is pinned by its WireGuard key from the first packet, and the Outpost's private key never leaves its machine. The cost is a small Edge API inside the Tunnel, a state directory on every Outpost, and an Edge key that can't rotate without rekeying every Outpost.

See [Joining: how an Outpost enrolls with the Edge and is trusted](https://github.com/hyprsh/tnl/issues/6).
