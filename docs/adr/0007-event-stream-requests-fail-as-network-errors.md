# Event-stream requests fail as network errors

When the Edge can't reach a Route's Outpost or Service, it answers 503 or 502 with an error page, except to requests whose `Accept` includes `text/event-stream`. Those get a stream reset (HTTP/2, HTTP/3) or a closed connection (HTTP/1.1) and no status, while the Edge's log still records the status it would have sent. Every major browser's `EventSource` closes for good on any non-200 response but retries a network error every few seconds. So with an honest 503, an app's live updates would die the first time they reconnect into an offline Outpost or a Service mid-deploy, and stay dead until the page reloads. Nobody reads the body of an error sent to an `EventSource`, so the reset loses nothing and lets apps ride out the outage. We chose this over the status codes every other proxy sends, which would leave each app to reopen its own `EventSource` once it reaches CLOSED. The cost is a deliberate deviation that tools like `curl` see as an empty reply. Apps may also come to rely on the retry, so changing it later would quietly break them.

We checked this by hand on 2026-10-17 with v0.1.0 (#64), with Firefox, Chromium and Safari on macOS holding an event stream open while the Outpost was stopped. With the Outpost stopped for 150 s, every browser kept retrying the reset and resumed from its `Last-Event-ID` once the Outpost was back, so the fallback of answering `200` and closing was not needed. Two Edge problems showed up along the way: a stream cut by a stopped Outpost can stay open until TCP keepalive gives up, so the browser can't retry until then ([#79](https://github.com/hyprsh/tnl/issues/79)), and once the Outpost is Offline some browsers retry the immediate reset several times a second ([#84](https://github.com/hyprsh/tnl/issues/84)).

See [Reconnects: what visitors see when an Outpost or Service is down](https://github.com/hyprsh/tnl/issues/14).

Amended by [ADR 0013](0013-event-streams-get-retry-not-a-reset.md): the reset gave way to `200` with a `retry:` field and a closed stream, to bound the retry rate.
